# Vercel AI SDK + OCP

AI SDK Core's `generateText` behind the OCP TypeScript SDK (`@openchannelprotocol/sdk`). An
inbound `message.received` envelope goes through `openChannel()`,
`generateText` produces the answer, and the text is dispatched as an OCP
`message.sent`.

Code layout:

- `src/main.ts`: the `generateText` call and model selection.
- `src/ocp-bridge.ts`: the OCP wiring (app, agent, channel, policy, store).

This is a request/response path. OCP 2.0 does not yet standardize token
streaming, so streaming needs an application-specific extension and explicit
event mapping.

## Prerequisites

- Node.js 22.18 or later.
- An OpenAI API key. Create one at <https://platform.openai.com/api-keys>.
  This example has no offline mode, because a scripted model would skip the
  `generateText` call it exists to show.
- The `@openchannelprotocol/sdk` SDK. **It is not on the npm registry yet**, so `npm install`
  does not install it. The SDK also depends on other workspace packages, so it
  cannot be installed from `sdks/typescript` by npm alone. To run this example
  you must make `@openchannelprotocol/sdk` resolvable (for example, from a local build of
  `sdks/typescript`). The bridge typechecks against the SDK source; a
  standalone one-command install is not verified.

## Run

```bash
npm install --prefix examples/vercel-ai-typescript
export OPENAI_API_KEY=...   # never commit this value
npm start --prefix examples/vercel-ai-typescript
```

Pass a question after `--` to replace the default:

```bash
npm start --prefix examples/vercel-ai-typescript -- "What does OCP policy do?"
```

## Environment variables

| Variable         | Required | Default       | Purpose                                                                    |
| ---------------- | -------- | ------------- | -------------------------------------------------------------------------- |
| `OPENAI_API_KEY` | Yes      | none          | Read by `@ai-sdk/openai`. Startup fails with a message naming it if unset. |
| `OPENAI_MODEL`   | No       | `gpt-4o-mini` | Chat model passed to `openai(...)`.                                        |

## Expected output

The example prints JSON like this. `reply` comes from the model, so its text
varies between runs:

```json
{
  "agentCard": {
    "id": "agent:vercel-ai-sdk-agent",
    "name": "Vercel AI SDK Agent",
    "...": "..."
  },
  "correlationId": "<uuid of the inbound message.received>",
  "eventType": "message.sent",
  "reply": "<text generated by the model>"
}
```

## How this maps to OCP

- The input becomes a `message.received` envelope from `channel:example`, sent
  to agent `agent:vercel-ai-sdk-agent`.
- The AI SDK owns model execution. The reply leaves through OCP as
  `message.sent`.
- The example registers no actions, and its policy denies every action target.
  Tool calls from `generateText` must go through OCP action and approval events
  before they change state.
